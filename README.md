# 经典《帝国时代 II》中文与原生宽屏实测记录

本教程记录一份经典《征服者》1.0 衍生数据包在 Windows 11 上恢复简体中文，并使用原生 1366×768 对局画面的实测过程。首次验证于 2026-10-10，运行副本在 2026-10-15 恢复，用户于 2026-10-16 确认鼠标操作恢复正常。

这是原创教程、配置示例和只读校验工具。它不提供游戏程序、素材、修改后的 EXE/DRS、个人存档或第三方工具二进制。本文记录的一份旧游戏构建已验证成功；其他版本必须重新核对兼容性。

## 三个问题分别处理

1. **中文变成问号**：游戏使用 ANSI 文字接口，系统代码页 932（日语）不能完整表示简体中文。本次已有宋体等中文字体，按程序模拟代码页 936 后文字恢复。
2. **全屏输出与原生分辨率**：把 1024×768 输出成 1366×768，可以保持比例留黑边，或拉伸铺满。原生宽屏则需要内部画面宽度与界面一起变成 1366，保留人物比例并增加横向视野。
3. **现代 Windows 显示兼容**：本次采用 cnc-ddraw；原生画面与输出同为 1366×768，`maintas=true` 保持比例，不进行横向拉伸。

## 本次实测结果

- 原生对局画面为 1366×768，无左右黑边，人物和建筑比例正常。
- 中文正常；用户确认单位移动、小地图和底部按钮正常。
- 原来的 EXE、兵种/科技 DAT、界面 DRS 和语言 DLL 未被改写，采用独立运行副本。
- 首次测试退出后桌面恢复原分辨率；这项观察不代表每台电脑都具有相同的显示模式。
- 恢复运行副本后曾出现“指针跟随正常、点击落点不一致”。用户重启电脑后确认偏移消失，最终保留原配置；具体原因尚未确定。
- 主菜单仍使用老版 800×600 布局。这里的“原生宽屏”指对局画面，不代表所有菜单都重新设计。
- 没有单独进行新存档保存后回读测试，也没有据此宣称所有扩展包、多人联机或所有 Windows 版本都兼容。

## 可直接使用的材料

- `scripts/check_installation.py`：只读计算版本指纹、识别本案例已测构建；不修改游戏或安全设置。
- `configs/cnc-ddraw-native.ini`：原生 1366×768 的输出配置示例。
- `configs/locale-emulator-zh-CN.example.xml`：按程序模拟中文环境的配置示例。

例如在 Windows 的终端运行：

```text
python scripts/check_installation.py --game-dir "你的游戏目录"
```

工具只识别指纹并显示结果，**不是原生补丁安装器**。原生生成算法参考的历史项目没有明确许可证，因此不在此草稿中搬运或重新许可。

## 如何使用这份记录

1. 先对自己的游戏目录运行只读校验工具，核对程序构建。文件指纹不匹配时，本案例的原生尺寸结论不适用。
2. 从 [Locale Emulator 官方发布页](https://github.com/xupefei/Locale-Emulator/releases/tag/v2.5.0.1)获取工具，为该程序建立 `zh-CN` 配置，保留原有时区。参考配置只针对这个进程，不需要改变系统区域语言。
3. 保持原始安装与实际运行副本分开。副本需要完整的运行资源；只有一个 EXE 和显示 DLL 不够。原生程序和相应的宽屏界面资源必须是已经核对匹配的一组。
4. 如果已经具备与本案例匹配的原生构建，把显示配置示例用于运行副本。标准 1024×768 程序配合这份 INI 仍不会获得原生宽屏；本教程不负责生成或提供该构建。
5. 建立中文启动快捷方式，并逐项验证中文、对局尺寸、单位选择、右键移动、小地图和底部按钮。快捷方式的参数与“起始位置”见[启动与迁移说明](docs/case-study.md#启动入口与迁移)。

迁移游戏或恢复文件后，重新核对快捷方式所指的程序、中文配置和工作目录。显示正常与点击正常需要分别确认。

## 鼠标偏移的记录

本案例恢复后曾出现点击错位，最终用户在重启后确认正常。原生 EXE、界面资源和显示兼容 DLL 保持已验证版本，最终 INI 也恢复原配置；试验中的鼠标参数没有作为修复方案保留。

这是一次结果记录，不能据此保证重启能解决所有偏移。遇到同类问题时，先确认实际使用的运行目录、内部与输出分辨率、系统缩放和工作目录，再用本机鼠标验证，避免把“图像已铺满”当成输入坐标也已正确。
