# 已验证案例：中文与原生 1366×768

首次测试发生于 2026-10-10（Asia/Tokyo），此后于 2026-10-15 恢复运行副本，并于 2026-10-16 收到用户的鼠标正常确认。这是一份单机实测记录，不是所有版本通用的补丁说明。

## 版本指纹

| 项目 | 本次输入 |
| --- | --- |
| 游戏程序 | `age2_x1.exe`，经典《征服者》1.0 构建 |
| FileVersion | `00.07.22.0627` |
| 长度 | `2695213` 字节 |
| MD5 | `b1b52d891550029adefd6a0a5c33ecbe` |
| SHA256 | `f6c331dd78f5f8a63fbc08f49963733623482c4bd017bfc6426c6971d139a5d1` |
| 原界面 DRS SHA256 | `0b19013c4f68ca1b657a9fbbcc197bcd86c3201185d63f61b3dace3d90ae8091` |
| 数据包特点 | 简体中文与自定义扩展资源；原单位和科技数据保持原样 |

MD5 用于对照历史工具的版本表，SHA256 用于完整性记录。两者都不能证明游戏所有权、来源安全或适配所有版本。

## 中文编码

本机系统给旧程序使用代码页 932（日语），已装宋体、黑体和微软雅黑。EXE 导入 `LoadStringA`、`TextOutA` 等 ANSI 接口；语言 DLL 中保留正确的 Unicode 中文。

本次读取能复现“随机地图→随机地?”、“存档游戏→存档游?”。Locale Emulator 的 `zh-CN` 配置让测试进程使用 ACP/OEMCP 936、LCID 2052；相同文字恢复，系统区域语言保持原样。东京时区保留，没有为了中文改变整个系统区域。

## 原生加宽

历史源码参考：[withmorten/aoe2wide，固定 commit](https://github.com/withmorten/aoe2wide/tree/650a599e88223bab2e5e6f7ac02ffecb287135f9)。项目保留 BoekaBart 的历史作者记录，目前没有明确 LICENSE。

本次原程序与历史 `myth` 构建指纹匹配，185 个待修改位置的原值全部匹配。新程序只改变 88 个 DWORD、合计 160 个字节，涉及显示尺寸、界面坐标和新界面文件名。这里没有分发该补丁表或衍生算法。

界面 DRS 有 397 项：19 个单帧 SLP 从 1024×768 加宽到 1366×768，378 个非目标资源 payload 保持逐字节相同。兵种、科技数据与语言文件未被替换。

已验证输出指纹（仅记录，不提供文件）：

| 产物 | SHA256 |
| --- | --- |
| 原生 EXE | `6949cbfcbc680bb45aa3bb9db56abfa098c49e13c95a6973c3662f2553a00b9a` |
| 新界面 DRS | `dad1489f838163e75140d4da0d54a332cacf77f86c75194bc0356951010915c9` |

这份固定分辨率程序需要通过 `1024` 参数选择被转换的旧槽位。参数名仍是 `1024`，内部对局画面实际为 1366×768；不要据此把其他分辨率槽当作可用模式。

## 启动入口与迁移

原始安装与独立运行副本分开。后者包含完整的游戏依赖、已验证的原生 EXE、匹配的宽屏 DRS，以及该副本使用的显示兼容文件。中文环境工具放在另一个目录，启动入口通过它运行副本中的程序。

快捷方式各项需要同时正确：

| 项目 | 设置 |
| --- | --- |
| 目标程序 | Locale Emulator 发布包中的 `LEProc.exe` |
| 命令参数 | `-runas <中文配置的 Guid> "<运行副本中原生 EXE 的完整路径>" 1024 nostartup` |
| 起始位置 | 原生 EXE 所在的运行副本目录 |
| 中文配置 | `Location=zh-CN`；时区保留用户原设置 |

上表的尖括号是需要替换的占位符。配置的 Guid 从自己的 `LEConfig.xml` 中读取；若采用仓库的配置示例，则与示例中的 Guid 保持一致。Windows 快捷方式的“目标”栏通常把目标程序与命令参数写在同一栏，带空格的路径需要引号。

`1024 nostartup` 是本案例构建的已验证参数，不能作为所有游戏版本的通用宽屏命令。此教程不提供原生 EXE、DRS 或生成器。

复制到新位置时，重新生成快捷方式，更新目标、程序参数内的路径和“起始位置”。保留完整运行副本与中文工具目录，并检查宽屏资源是否存在；只复制快捷方式或 EXE 不足以迁移这套运行环境。

## 显示兼容

已采用 Locale Emulator 2.5.0.1 和 cnc-ddraw 7.1.0.0 的组合，采用 Direct3D9、`nonexclusive=true`、`adjmouse=true`。

cnc-ddraw 中 `windowed=false` 与 `fullscreen=false` 保留指定全屏输出尺寸；`fullscreen=true` 会使用当前桌面尺寸。这两个参数的名称容易误解，须按上游文档和实际显示模式验证。

`maintas=true` 保持画面比例：原内部画面为 4:3 时会留黑边，已经原生加宽成 1366×768 后，对局输出不需要拉伸。

该版本 cnc-ddraw 会临时写入四个当前用户 Indeo 视频解码器映射，正常卸载后删除。本次初始四项均不存在，退出后已检查；这不能被描述为所有机器都“绝不改注册表”。已有映射的机器需要额外保全和验证。本教程不提供更改这些项的脚本。

## 后续恢复与鼠标偏移

| 日期 | 观察与处理 |
| --- | --- |
| 2026-10-10 | 中文和原生 1366×768 对局验证成功，用户确认单位移动、小地图和底部按钮正常。 |
| 2026-10-15 | 重新补齐独立副本的运行文件，恢复匹配的宽屏界面资源与中文配置，并重建启动入口。中文、对局尺寸、画面比例、菜单和小地图验证通过。 |
| 2026-10-15 | 用户报告指针能够跟随，但点击位置与实际响应不一致。自动化输入也出现选单位时镜头跳到地图边缘，不能仅凭截图判定操作正常。 |
| 2026-10-16 | 用户重启电脑后确认鼠标偏移消失、当前操作正常。保留原显示兼容 DLL 与原基准 INI，未保留试验性的鼠标参数。 |

恢复后的原生 EXE、宽屏 DRS 和显示兼容 DLL 均与此前成功版本匹配。INI 仍使用 `nonexclusive=true`、`adjmouse=true`、`maintas=true`，快捷方式仍为 `1024 nostartup`，没有追加鼠标模式参数。

偏移消失的具体原因尚未确定。重启前后的用户反馈说明这台电脑最终可用，但不能证明某个兼容开关修复了问题，也不能把重启写成所有机器必然有效的解决办法。

可复用的检查顺序是：先确认启动的确实是预期副本，再核对 EXE 与界面资源是否匹配、快捷方式工作目录、内部与输出分辨率和系统缩放，最后用本机鼠标分别测试单位选择、移动、底部按钮及小地图。每次只改变一个候选设置，验证无效就恢复；最终记录实际保留的配置。

## 验证与未验证范围

已验证：

- 进入对局后截图为 1366×768，左右无黑边、人物建筑比例正常、中文正常。
- 用户确认移动单位、小地图及底部按钮正常。
- 原有游戏程序和数据完整性保留。首次 2026-10-10 的测试还按不覆盖方式补齐过存档与录像；这属于当时的历史操作，并非本教程的自动功能。
- 首次测试窗口内未发现原生运行的应用崩溃事件，退出后桌面恢复原分辨率；不据此保证长期运行无崩溃。
- 2026-10-15 恢复后，中文与原生尺寸再次验证；2026-10-16 用户确认重启后鼠标点击恢复正常。该项依据用户实测反馈，没有另行宣称自动化完成了所有单位操作测试。

未单独验证：新存档保存后回读、多局长时间运行、多人联机、其他游戏构建及其他扩展包。

应用控制最初返回错误 4551，后来正常创建进程和对局通过。用户报告有手动处理；助手没有修改安全策略，读回值也不能单独证明全系统保护状态已改变，因此不将“关闭保护”列为复现步骤。
